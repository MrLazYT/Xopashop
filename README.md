# XopaShop 4.0

React + TypeScript + Node/Express прототип магазину XopaShop. У цій версії додані адмін-панель, фото товарів, детальні сторінки товарів, розширений кабінет і повний трекінг замовлень.

## Маршрути

- `/` — Головна
- `/departments` — Відділи
- `/sales` — Акції
- `/buyback` — Викуп
- `/other` — Інші ігри, конкурси та нетипові товари
- `/about` — Про нас
- `/account` — Персональний кабінет
- `/search?q=...` — Пошук
- `/product/<id>` — Детальна сторінка товару
- `/track?code=<код>` — Відстеження замовлення
- `/admin` — Адмін-панель

## Що нового у 4.0

- окрема адмін-панель;
- CRUD товарів: додавання, редагування, видалення;
- завантаження зображень товарів у `/uploads`;
- детальна сторінка товару: фото, опис, ціна, наявність, деталі, уточнення, відгуки;
- пошук працює по локальному каталогу/backend незалежно від Telegram;
- трекінг у вигляді маршруту + вертикального журналу подій;
- доставка на територію/адресу, за координатами або до хопамату;
- хопамати зберігаються в `data/store.json` та керуються з адмін-панелі;
- адмін може додавати кожну нову подію трекінгу із місцем і приміткою;
- персональний кабінет: статистика, профіль, Telegram, історія замовлень, швидкі дії;
- новий логотип XopaShop + favicon;
- головна сторінка стала коротшою: hero, відділи, гарячі пропозиції, коробка/Telegram, акції, відгуки;
- backend сам рахує суму товарів за серверним каталогом, а не довіряє `total` з браузера.

## Запуск

Потрібні Node.js 20+ та npm.

```bash
npm install
```

Термінал 1 — backend:

```bash
npm run server
```

Backend: `http://localhost:8787`

Термінал 2 — frontend:

```bash
npm run dev
```

Frontend: `http://localhost:5173`

Перевірка backend:

```text
http://localhost:8787/api/health
```

## Налаштування `.env`

Скопіюй `.env.example` у `.env`:

```env
VITE_API_URL=http://localhost:8787
VITE_TELEGRAM_SHOP_URL=https://t.me/YOUR_XOPASHOP_CHANNEL
VITE_TELEGRAM_BOT_URL=https://t.me/YOUR_XOPASHOP_BOT

TELEGRAM_BOT_TOKEN=BOT_TOKEN_FROM_BOTFATHER
TELEGRAM_ADMIN_CHAT_ID=YOUR_CHAT_ID
PORT=8787
ADMIN_KEY=LONG_RANDOM_PASSWORD
PUBLIC_SITE_URL=https://your-domain.example
```

`TELEGRAM_BOT_TOKEN` ніколи не клади у `VITE_*` змінні.

## Адмін-панель

Відкрий:

```text
http://localhost:5173/admin
```

Введи значення `ADMIN_KEY` із `.env`.

Доступні розділи:

- **Товари** — назва, категорія, гра, ціни, склад, badge, опис, фото, деталі, уточнення;
- **Замовлення** — перегляд і додавання подій трекінгу;
- **Хопамати** — адреса, територія, координати, примітка;
- **Відгуки** — схвалення/приховування;
- **Про нас** — контентні блоки;
- **Користувачі** — список акаунтів.

### Фото товару

У редакторі товару можна:

1. вставити готовий URL зображення;
2. вибрати локальний файл через кнопку **Файл**.

Backend збереже файл у каталозі `uploads/` і поверне URL.

## Замовлення і доставка

Користувач при оформленні обирає один варіант:

- **Територія / адреса** — вільний текст;
- **Координати** — наприклад `X 124, Y 65, Z -340`;
- **Хопамат** — вибір зі списку, який веде адміністратор.

Доставка додається до підсумку окремим рядком як 25 діямантів.

## Трекінг

Кожне замовлення має `trackingEvents`. При створенні автоматично додається перша подія. Далі адміністратор у `/admin` відкриває замовлення та додає:

- статус;
- місце/територію;
- примітку.

Користувач відкриває `/track` і вводить код замовлення. Відображаються поточний статус, адреса/хопамат і повна історія подій.

## Telegram товари

Webhook як і раніше підтримує імпорт постів із каналу. Формат:

```text
#product | Назва | department | price | oldPrice | imageUrl | stock | game
```

Наприклад:

```text
#product | Плакучий обсидіян | products | 64 | 80 | https://site/image.png | 32 | Minecraft
```

Але **Telegram не потрібен для роботи пошуку**: пошук використовує каталог, який вже завантажений у сайт/backend.

## Дані

Зараз дані зберігаються у:

```text
data/store.json
```

Це зручно для локальної розробки й першого прототипу. Для production я рекомендую перенести `users`, `orders`, `products`, `reviews`, `hopamats` у PostgreSQL або SQLite/PostgreSQL ORM. Також варто додати rate limiting, HTTPS, резервні копії та нормальну адмін-авторизацію замість одного `ADMIN_KEY`.
